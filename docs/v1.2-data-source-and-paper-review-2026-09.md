# V1.2 数据源与近期论文复核报告

检索日期：2026-09-08

## 结论先行

1. 本轮没有找到满足“中文、公开可下载、邮件正文级、许可证可审计、非纯模板/非纯 LLM 生成、可覆盖近年攻击”的合格中文训练集。
2. 中文公开数据路线在 V1.2 阶段关闭。现有 LLMGen 中文集不进入训练，Twente 数据集不进入训练；二者只保留为审计记录，必要时作为鲁棒性/验证参考。
3. Sting9 理论字段最符合 V1.2 设计，但截至 2026-09-08 无法形成可重复的公开下载路径：研究入口显示数据下载 Coming Soon，API 需要注册和 JWT。因此暂不使用。
4. 近期论文大多仍使用历史英文语料。论文发布时间较新，不代表样本较新；不能用 2024/2025 论文证明模型覆盖了 2022--2026 攻击。
5. V1.2 不再通过堆叠历史语料扩大训练集。后续重点转为清洗、来源/活动隔离、硬负样本、行为意图标注，以及保留 20K--30K 的受控训练规模。

## 中文数据检索结果

### LLMGen-Phishing-Email-Dataset

Hugging Face 页面显示该集包含中文和英文/混合邮件，2025 年发布，Apache-2.0 数据集卡。但本地审计已确认其为生成数据，字段只有正文和二分类标签，缺少可信的原始邮件头、活动、时间和来源信息。结论：不用于正式训练或独立测试，只能作为生成文本鲁棒性参考。

### Twente Phishing Validation Emails

Zenodo 记录 13474746 于 2024-08-29 发布，CC BY 4.0，包含 2,000 封全文邮件，1,000 Safe 和 1,000 Phishing。数据说明明确包含真实与人工生成邮件，定位是验证模型而非训练模型。结论：可审计、可下载，但不用于 V1.2 训练。

### Sting9

数据页描述了邮件正文、脱敏 raw headers、语言、攻击类型、原始时间戳、发件域、URL 和附件元数据，理论上非常适合多视图模型。页面同时声明 CC0 和每周 GitHub dump；但研究入口当前把数据下载标记为 Coming Soon，API 需要研究者注册/JWT，公开 GitHub 地址也未形成可重复下载入口。结论：暂不可用，状态记为 failed，待公开转储重新可复现后再审计。

### 其他中文来源

检索到的中文相关结果主要是：翻译英文邮件、LLM 生成中文邮件、中文论文中的私有或未公开样本，以及邮箱探测/URL 数据。它们不满足本项目的“邮件正文级、公开可审计、真实来源”要求，因此不纳入训练。

## 近期论文复核

### Multilingual Email Phishing Attacks Detection using OSINT and Machine Learning（2025-01）

论文使用 2023 年发布的英文 Kaggle 邮件集，原始 18,651 条，去重后 17,522 条；再随机抽取 1,484 条，翻译生成阿拉伯语集，并增加 Nmap/theHarvester 的 17 个 OSINT 特征。论文报告 Random Forest 在英文和阿拉伯语 OSINT 集上约 97.37% accuracy。

可借鉴点：语言分层评估、去重后再划分、结构化域名/URL 特征与正文特征分离。

不可直接借鉴点：阿拉伯语样本由翻译生成，不是真实多语言攻击语料；Nmap/theHarvester 会访问外部网络，与本项目“邮件 URL 不外联”的安全约束冲突。V1.2 只能采用离线 URL 结构特征。

来源：`https://arxiv.org/html/2501.08723v1`

### MeAJOR Corpus（2025-11 论文，2026-02 Zenodo 数据）

论文和 Zenodo 记录描述 108,685/135,894 级别的多来源语料，来源包括 Enron、Nazario、Nigerian Fraud、TREC-05/06/07、Ling-Spam 等。数据已做实体脱敏，并提供 CSV/Parquet 与 URL、附件等工程特征。论文报告 XGBoost 在 Text+URL 特征上 F1 约 98.34%。

可借鉴点：明确区分 Text、Text+URL、Text+Attachment；把 URL 结构作为独立视图；对来源、标签和脱敏过程做统一记录。

不可直接使用原因：主要是历史公开语料的合并与预处理，并不等同于近四年攻击数据；规模远超 V1.2 目标；若直接引入会重复已有历史语料并放大来源泄漏风险。

来源：`https://arxiv.org/html/2507.17978v2`；`https://zenodo.org/records/18471483`

### 2024 年多模型/深度学习论文的共同模式

近期论文普遍使用 Enron、Nazario、SpamAssassin、TREC、Ling-Spam 或 Kaggle 派生集。常见模型包括 Random Forest、XGBoost、SVM、Logistic Regression、CNN、MLP 和 Transformer。论文中较高的 F1/accuracy 往往来自随机划分、重复语料或容易识别的模板特征，不能直接推断对新活动、中文和 BEC 的泛化能力。

对本项目最有价值的共识是：

- 正文、URL、附件、头部和 HTML 应作为独立视图评估；
- URL 特征通常比附件计数更稳定，但不能通过访问 URL 获取特征；
- 结构/头部异常与行为意图是互补信号；
- 必须按来源、活动和时间分组留出测试，而不是只做随机切分。

## V1.2 决策

### 数据使用决策

- LLMGen：不训练主模型；可用于生成文本鲁棒性检查。
- Twente：不训练；保留为独立验证参考。
- Sting9：暂不下载，状态为 failed。
- MeAJOR：不直接下载；只参考其字段设计和实验方法。
- 历史英文语料：不再新增；已有 V1/V1.1 语料保留用于基线和硬负样本。

### 中文能力路线

V1.2 不再等待公开中文训练集。中文能力通过以下方式验证：

1. 保留并扩展人工脱敏中文回归集；
2. 构造“中文正常通知 vs 中文诱导操作”的成对样本，专门验证 intent 分支；
3. 使用中文字符 n-gram、语言标识和结构/URL/头部视图，不把中文关键词当作唯一证据；
4. 将中文集设为独立测试集，不参与主训练集拟合；
5. 后续若获得真实中文邮件，必须单独记录来源、时间、活动和许可，不能直接混入已有分桶。
